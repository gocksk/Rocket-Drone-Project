## 설계 원칙 3개

### 1. 단일 사이징 루프
되먹임 상태는 MTOW 하나입니다. 무게에 반응하는 질량(구조·모터·배터리)은 전부 루프
본체 안에서 MTOW의 함수로 계산됩니다.

### 2. 모듈 = 파일 = 담당
한 분야의 일을 여러 파일로 쪼개지 않습니다. 세부 실행 단위는 모듈 안의 함수로 두고,
통합 런처가 호출해 조립합니다.

### 3. 상수보다 해석식
설계변수에 반응해야 하는 물리량을 눈금 상수로 대체하지 않습니다.
상수는 "설계공간에 반응할 필요가 없는 양"에만 씁니다.

> **원칙 3이 뭘 막는가**
> 어떤 양을 "다른 값에 계수를 곱해서" 만들면, 그 양은 곱한 변수의 함수일 뿐이라
> 설계공간에 반응하지 않습니다. 예를 들어 최고속도를 "요구속도 × 여유계수"로 만들면,
> 동체를 아무리 날씬하게 만들어도 최고속도가 변하지 않습니다. 그러면 그 지표를 EC로
> 쓸 수 없습니다.
> 그래서 이 판에서는 순항 자세·최고속도·모터 전류·외란 모멘트를 전부 **풀어서** 얻습니다.

## 1. 코드가 하는 일 한눈에

**목표**: 300 km/h · 요구 거리 · 호버를 만족하도록 부품을 사이징하고, 그 위에서 가장
완성도 높은(빠르고·가볍고·작고·멀리 가고·안정적인) 설계를 찾는다.

설계 후보 하나를 넣으면 아래 순서로 계산됩니다.

```
[입력: 설계변수(Design points)] + 고정상수(invariant values)

 ⓪ 전처리 — 무게·부품과 무관, 설계점당 1회
    atm.run() → geom.hull() → aero.run() → prop.build_map()

 ① 사이징 루프 — MTOW 하나를 수렴시킨다
    resp_of(MTOW):
       prop.size_motor(MTOW, …)      → m_mot            [트림 연립 + 열 한계 + 팁마하]
       miss.required_energy(MTOW, …) → E_batt, m_batt   [요구 임무 실적분]
       strc.run(MTOW, …)             → m_str
       return 응답질량 합
    wght.converge():  MTOW = 고정질량 + resp_of(MTOW)

 ② 후처리 — 수렴값으로 1회
    geom.layout() → geom.check_fit    [g6·g7]
    → prop.evaluate                   [V_max 실계산 → C3, C6, kv]
    → miss.achieved_range             [C2]
    → stab.run                        [C5, g8·g9]
    → cost.run                        [C7]

[출력: 성적표 C1~C8 + 합격조건 + 요구 부품 스펙 시트 + 진단 변수]
```

부품(모터·배터리)은 고르는 것이 아니라 **계산되는 것**입니다. 요구조건을 만족하는
최소 스펙을 코드가 직접 풀고, 그 위의 여유만 탐색합니다.

이 계산을 수천 개 후보에 반복해 가장 좋은 설계점을 찾는 것이 C2 단계입니다.

## 2. 설계 변수

최적화가 이 값들을 바꿔가며 좋은 조합을 찾습니다.

> **pd_prop 하한 규칙** — `[개정 §11-9 · 승인됨]` 계수 **1.05 → 1.25**
> DOE 범위를 잡을 때 피치속도 ≥ **1.25** × V_cr 이 되도록 하한을 설정합니다.
> 이 규칙 밖의 표본은 전처리에서 즉시 탈락하므로 애초에 뿌리지 않습니다.
>
> 등가 표현 (팁 마하 한계에서 도는 순항 전진비 `J_cr` 기준):
> ```
> V_pitch ≥ m·V_cr   ⟺   pd_prop ≥ m·J_cr
> J_cr = π·V_cr / √((M_tip_max·a)² − V_cr²)
> ```
> `J_cr` 는 **`d_prop` 에 무관**합니다 (`n_max = v_rot/(πd)` 에서 지름이 약분됨).
> `M_tip_max=0.7`, `V_cr=83.3` 에서 `J_cr = 1.173` → **`pd_prop` 하한 = 1.466**.
>
> 원문의 m=1.05 는 작동 전진비를 추력 0 전진비 `J₀ ≈ pd_prop` 바로 밑에 붙여 놓아
> 순항 CT 가 0.012 까지 무너집니다. m=1.25 에서 CT=0.065 로 **5.4 배**입니다.
> 근거·표는 §11-9. 판정 g1(§6.1)은 원문 정의 그대로 두었습니다 — 이건 판정이 아니라
> **표본을 뿌릴 범위** 규칙입니다.

## 4. 해석 규약

### 4.1 순항 트림 — 2식 연립

순항 요구추력은 미지수 (T, θ)에 대한 평형 2식을 **연립해서** 얻습니다.

> `[개정 §11-11 · 승인됨]` 원문의 식
> `T·cosθ + L(α)·sinθ = W`, `T·sinθ − D(α)·cosθ = 0` 은 어떤 좌표 규약으로도
> 닫히지 않습니다(근거 §11-11). 좌표 규약과 함께 아래로 바로잡았습니다.

```
규약:  θ = 자세각, 수평 기준.  θ=90° 호버(기수 수직),  θ→0 순항(기체 수평)
       α = 받음각.  순항 비행경로각 γ=0(수평비행) 전제  →  α = θ

       T·sinθ + L(V, α) = W        (수직 평형)
       T·cosθ           = D(V, α)  (수평 평형)
```

L=0 이면 `T = √(D²+W²)`, `tanθ = W/D` 로 정확히 환원되고, L>0 이면 T 가 그보다
작아집니다 — 이 절이 얻으려는 동체 양력 크레딧이 부호까지 맞습니다.
θ=90° 를 넣으면 `T = W`, 수평식은 `0 = D(V=0) = 0` 이라 추력지지와 일치합니다.

재료는 이미 있습니다 — AERO가 `CN_alpha`(Barrowman)와 항력 빌드업을 제공합니다.
2×2 뉴턴 반복 수 회. 수렴 실패 시 해당 설계점은 infeasible입니다.

적용 범위: 순항·dash 전 구간. 호버(θ ≈ 90°)는 추력지지 그대로입니다.

> **왜 √(항력² + 무게²)로는 안 되는가**
> 그 식은 동체·핀 양력을 0으로 두는 근사입니다. 현행 코드 실행 결과의 순항 자세각이
> 51.8°인데, 이 각도에서 동체 양력을 버리는 것은 "보수적"인 정도가 아니라 물리를
> 통째로 빼는 것입니다.
> 결과적으로 요구추력 → 동력 → 배터리 → 무게 사슬 전체를 계통적으로 과대평가하게 됩니다.

### 4.2 최고속도 — 평형 실계산

`prop.evaluate`는 최고속도를 여유 변수에서 읽지 않습니다. 확정된 파워트레인
(모터·프롭·배터리)으로 추력 = 항력 평형을 만족하는 V_max를 직접 풉니다
(V에 대한 1차원 이분법, U_eval 기준).

이로써 C3(속도 여유)가 형상·프롭 전체에 반응합니다 — 항력이 낮은 동체, 전진비 특성이
좋은 프롭이면 같은 모터로도 최고속도가 높아집니다.

> ⚠ **예상되는 현상**: 최적화가 "항력을 줄여 속도를 버는" 방향으로 강하게 끌립니다.
> 동체를 가늘고 길게 만드는 압력이 C8(보관 전장)·STAB와 충돌하는데, 이것이 이 기체의
> 진짜 트레이드오프이며 드러나는 것이 정상입니다. 최적해가 `d_body` 하한이나
> `lambda_body` 상한에 붙어도 범위 오류로 오독하지 마세요.

### 4.3 모터 전기 모델

고전 DC 모터 모델을 씁니다. **상수 효율 가정은 금지합니다.**

```
I = T/K_t + I0 ,   U = I·R_mot + ω/K_v ,   K_t = 60/(2π·K_v)
```

`R_mot`·`I0`는 모터 스펙표 3~5종의 회귀 f(m_mot, kv)로 얻습니다.
부하율에 따른 효율 변화가 자동 반영됩니다.

동손 I²·R_mot 이 열 모듈의 발열원입니다 — 이 모델 없이는 열 계산이 성립하지 않습니다.

### 4.4 외란 모멘트

`M_dist`를 상수로 두지 않습니다. 물리적으로 풍하중이므로 동압과 형상의 함수입니다.

```
M_dist = q · S_ref · CN_α · Δα · |x_cp − x_cg|
```

AERO가 `CN_alpha`·`x_cp`를, WGHT가 `x_cg`를 냅니다. 새 상수는 Δα(기준 돌풍 받음각)
하나입니다. 이로써 g8·g9가 임의 문턱값이 아니라 형상에 반응하는 물리 판정이 됩니다.

### 4.5 평가 전압

전압 의존 성능(V_max, 추력 한계)은 방전 말기 최악 상태로 평가합니다.

```
U_eval = U_cell(1−DoD)·n_ser − I_dash·R_pack
```

### 4.6 커널 공유 — 이중 구현 금지

미션 적분기는 **하나**입니다: `miss.integrate`. 사이징용(`required_energy`)과
평가용(`achieved_range`)은 같은 커널의 다른 진입점일 뿐입니다.

작동점 풀이도 하나입니다: `prop.solve_point`을 `size_motor`와 `evaluate`가 공유합니다.

같은 물리를 두 번 구현하면 반드시 갈라집니다.

### 4.7 기타

- 인터페이스 변수는 SI 기본 단위 (에너지만 Wh 허용). 관례 단위 변환은 모듈 경계 안에서만.
- 접두어: `W_`[kg] `P_`[W] `E_`[Wh] `T_`[N] `F_`[N] `U_`[V] `I_`[A] `eta_`[-] `n_`[-] `k_`[-] `Cost_`[KRW]
- 항력계수 기준면적은 동체 전면적 `S_ref`.

### ▶ 사이징 루프 상세

#### 1. 구조

```python
def resp_of(MTOW):                       # 순수 함수: MTOW → 응답 질량 합
    m_mot, diag_p = prop.size_motor(MTOW, pt_map, aero, ...)
    E_batt, m_batt, diag_e = miss.required_energy(MTOW, m_mot, ...)
    st = strc.run(dv, hull, aero, MTOW)
    return m_mot + m_batt + m_pack + st.m_str, payload(st, E_batt, diag)

res = wght.converge(m_fixed = W_pl + W_avio, resp_of = resp_of)
```

- 되먹임은 MTOW 하나입니다. `E_batt`·`m_mot`은 독립 상태가 아니라 반복 본체의 중간 계산값입니다.
- `geom.layout`은 루프 밖(②)입니다. 배치가 내는 것은 부품 위치뿐이고, 위치를 쓰는
  무게중심·관성은 수렴 후 1회 계산합니다. 반복 본체는 질량 합만 씁니다.
- 팁마하 판정은 `size_motor` 안에서 즉시 합니다. 한계 안에서 요구 추력을 낼 rpm이
  없으면 사이징 자체가 성립하지 않으므로, 후처리로 미루면 루프가 무의미한 값으로 돕니다.
- 초기값 MTOW₀ = `k_init` × m_fixed. 수렴값에 영향 없고 반복 횟수에만 영향을 줍니다.

#### 2. 수렴 · 발산 분류

반복이 안 끝나는 이유를 "되나/안 되나"가 아니라 **"왜 안 되나"로** 나눕니다.
책임 소재가 서로 다르기 때문입니다.

| status | 뜻 | 처리 |
|---|---|---|
| `converged` | 정상 수렴 | ②로 진행 |
| `diverged_structural` (Ŝ ≥ 1) | 무게 스노우볼 — 무게↑ → 동력·에너지↑ → 무게↑ 가 감쇠하지 않음 | 성립 불가 설계점. infeasible, 사유 기록 |
| `diverged_numerical` | 우리의 완화계수(beta) 선택 문제 | 재시도 가능 — 정상 설계점일 수 있음 |
| `limit_cycle` | 이산화 한계까지 수렴 | 탈락시키지 않음 |
| `max_iter` | 반복 소진 | 잔여 오차 동반 보고 |

탈락 사유 코드는 DOE 로그의 **1급 데이터**입니다. "설정 탓"과 "물리 탓"을 한 색으로
뭉개면 정상 설계점이 조용히 후보에서 빠집니다. 런처는 status를 그대로 결과까지 전달합니다.

**성장계수 분해**: 수렴 이력에서 각 응답 질량의 민감도 S_i ≈ Δm_i/ΔMTOW (구조·모터·배터리)를
산출해 함께 출력합니다. Ŝ_total = Σ S_i 이며 "스노우볼에 누가 기여하는가"의 지도가 됩니다.

#### 3. 모듈 내부 순환

두 곳에 내부 순환이 있습니다.

- `size_motor`: 모터 크기 → R_mot → 효율 → 요구 동력 → 모터 크기
- `required_energy`: E_batt → R_pack → 전압 → 전류 → 소비 에너지 → E_batt

둘 다 **결정론적 이분법**으로 닫습니다. 직전 반복값 재사용은 금지입니다.

> **왜 직전 반복값을 쓰면 안 되는가**
> 직전 값을 기억하면 `resp_of`가 상태를 갖게 됩니다. 그러면 같은 MTOW를 넣어도 호출
> 순서에 따라 답이 달라지고, 배치 실행에서 설계점끼리 서로 오염됩니다.
> WGHT 검증의 순수성 테스트가 정확히 이것을 잡습니다.
> 이분법은 같은 입력에 항상 같은 출력을 주므로 순수성이 유지되고, 비용도 10~20회
> 평가로 예측 가능합니다.

> ⚠ 미션 적분은 **고정 스텝**으로 구현합니다. 적응 스텝은 잔차에 인공 노이즈를 만들어
> WGHT의 `resid_floor`·양자화 판정 논리를 흐립니다.

#### 4. 실행 시간

미측정. 트림 연립·모터 이분법·열 계산·미션 적분이 모두 반복 안에 있습니다.
단일 설계점 수렴 테스트(§8 D-1)에서 실측한 뒤 DOE 규모를 정합니다.

시간 단축이 필요하면 정확성을 훼손하지 않는 순서로: ① 초기값 웜스타트(인접 설계점의
수렴값 사용) ② 병렬 배치 ③ 적분 스텝 재검토. 모델 충실도를 낮추는 방식은 후순위입니다.

## 5.1 모듈별 입출력 · 계산

### ATM — 표준대기

**입력** — `h`: 고도 [m] (임무 프로파일에서 받음)

**출력**
- `ρ`: 공기밀도 [kg/m³] → AERO, PROP, THRM
- `T`: 온도 [K] → THRM
- `a_snd`: 음속 [m/s] → PROP (팁 마하 계산)
- `ν`: 동점성계수 [m²/s] → AERO (레이놀즈수 계산)

**계산 — ISA 대류권 공식**
```
T = T₀ − L·h
p = p₀·(T/T₀)^(g/LR)
ρ = p / RT
a_snd = √(γRT)  와  ν = μ(T)/ρ (Sutherland 식)
```
검산: h = 0에서 ρ = 1.225 kg/m³
종속성: 무게·설계변수 모두와 무관 → ⓪에서 1회만 실행

### GEOM — 외형 · 배치 · 내장 판정

함수 세 개의 실행 시점이 다릅니다. 하나는 전처리, 둘은 후처리입니다.

#### `hull(dv)` — ⓪ 외형 확정

**입력**: `d_body`, `lambda_body` / `S_fin`, `x_fin`, `AR_fin`

**출력**
- `S_ref`: 동체 전면적 [m²] → AERO, STAB — 항력계수의 기준면적
- `S_wet`: 젖음면적 [m²] → AERO
- `l_body`: 전장 [m] → 성적표 C8, STRC
- `r_body`: 동체 반경 [m] → STAB, check_fit
- 핀 기하: 코드길이·스팬 → AERO, STRC

**계산 — 대수 계산만, 반복 없음**
```
S_ref  = π·d_body² / 4
l_body = d_body × lambda_body
S_wet  = 노즈 표면적 + 원통 측면적 + 핀 양면
핀 스팬과 코드를 S_fin과 AR_fin에서 역산
```

#### `layout(dims)` — ② 부품 배치

**입력**: 부품 치수 (배터리 L·W·H, 모터 D·L, AVIO_LIST — 사이징 후 확정된 값), hull 출력 전체

**출력**
- `x_parts`: 기수 기준 각 부품 위치 [m] → WGHT (무게중심·관성), check_fit
- `arm_rotor`: 모터 암 길이 [m] → STAB, check_fit

**계산**
```
부품 부피를 밀도 상수로 환산 — 부피 = 질량 / rho_*
기수부터 배치 규칙 순서대로 쌓음 — 카메라 → 센서 → 배터리 → FC/ESC
```

> **왜 루프 밖인가**: 배치가 내는 것은 위치뿐이고, 위치를 쓰는 무게중심·관성은 수렴 후
> 1회만 계산합니다. 반복 본체는 질량 합만 쓰므로 루프에 둘 이유가 없습니다.

#### `check_fit(…)` — ② 판정

**입력**: `x_parts`, hull 출력, 부품 치수, `d_prop`, `arm_rotor`

**출력**
- `g6`: 내장 여유 — 가용 길이 − 부품 점유 길이 (단면 여유도 함께 검사)
- `g7`: 클리어런스 여유 — `arm_rotor − d_prop/2 − r_body − 안전여유`

규약: 둘 다 양수면 합격, 음수면 불합격입니다.

### AERO — 항력 빌드업 · 안정성 계수

**입력**: hull 출력 (S_ref, S_wet, l_body, 핀 기하) / ATM 출력 (ρ, ν, a_snd)

**출력**
- `F_drag(V, α)`: 속도·받음각별 항력 곡선 [N] → PROP, MISS
- `CL(V, α)`: 양력계수 → PROP — **트림 연립용으로 이 판에서 추가된 항목**
  > `[개정 §11-3 · 승인됨]` 원문 `CL(α)` → `CL(V, α)`. 풍축 변환의 축력항이 V 에
  > 의존합니다: `CL = C_N(α)·cosα − CD0(V)·sinα`
- `CN_α`: 법선력 기울기 [1/rad] → STAB
- `x_cp`: 압력중심 위치 [m] → STAB
- `S_ref`: 기준면적 [m²] — `[개정 §11-13 · 승인됨]` hull 출력의 사본. 트림이 `CL` 을
  힘으로 바꾸려면 `q·S_ref` 가 필요합니다
- `CN_α_fin`, `q_cr`: `[개정 §11-5 · 승인됨]` §5.1 STRC 입력이 요구하는 값

**계산**
```
성분별 항력 빌드업 — 동체 마찰(Re 기반 평판 상관식 × 형상계수)
                     + 핀 마찰·압력 + 기저 항력 + 간섭 항력
압축성 보정 — a_snd 대비 마하수로
법선력과 압력중심은 Barrowman 공식 — 노즈 기여 + 핀 기여
```

종속성: 무게·부품과 무관 → ⓪에서 1회만 실행하고, 반복 안에서는 이 곡선을 조회만 합니다.

**결정할 것**: α와 자세각 θ의 관계 정의 — 순항 비행경로각 가정이 필요하며, 트림 연립의 전제입니다.

### PROP — 프롭 맵 · 작동점 · 모터 사이징 · 평가

함수 다섯 개 중 `solve_point`이 나머지가 공유하는 심장입니다.

#### `build_map(dv)` — ⓪ 프롭 성능 맵

**입력**: `d_prop`, `pd_prop` / ATM 출력 (ρ, a_snd)

**출력**
- `CT(J)`, `CP(J)`: 추력·동력 계수의 보간 테이블 → `solve_point`
- `m_prop`: 프롭 질량 [kg] → WGHT, COST
- `g1`: 순항 성립 여부
- `d_prop`: 프롭 지름 [m] — `[개정 §11-13 · 승인됨]` `solve_point` 가 전진비
  `J = V/(nD)` 를 만들 때 필요합니다

**계산**
```
BEMT(블레이드 요소 + 운동량 이론)를 전진비 J 격자에 대해 미리 풀어 테이블로 저장
프롭 질량은 m_prop = k_mprop · d_prop³
g1 판정 — 피치속도(= pitch × 허용 최대 rpm)가 V_cr 이상인지
```

> **왜 루프 밖인가**: 무차원 계수는 프롭 기하만의 함수라 모터·무게와 무관합니다.
> 프롭을 설계변수로 남긴 덕분에 이 무거운 계산이 전처리에 머물 수 있습니다.

#### `motor_elec(…)` — 내부 DC 모터 모델

**입력**: `τ` 요구 토크 [N·m] / `ω` 각속도 [rad/s] / `kv`, `R_mot`, `I0` (f(m_mot, kv) 회귀에서 조회) / `U_bus` 버스 전압 [V]

**출력**: `I` 전류 [A] → MISS (SOC 감소 계산) / 요구 전압 (버스 전압과 비교해 성능 한계 판정) / `P_cu` 동손 [W] → THRM

**계산**
```
I    = τ/K_t + I0
U    = I·R_mot + ω/K_v
K_t  = 60/(2π·K_v)
P_cu = I²·R_mot
```

#### `solve_point(…)` — 공용 작동점 풀이

**입력**: V, MTOW, 모터 파라미터, CT/CP 맵, U_bus, AERO 곡선
**출력**: T, θ, rpm, I, P, kv

**계산 — 평형이 두 겹입니다**
```
기체 트림   : 미지수 (T, θ)에 대한 2×2 뉴턴 반복 (§4.1)
파워트레인 : 프롭 요구 토크 = 모터 발생 토크가 되는 rpm을 1차원 근찾기로 탐색
```
예외: 호버(θ ≈ 90°)는 1번을 건너뛰고 추력지지로 풀이합니다.
주의: `kv`는 이 토크 평형의 **해**로 나옵니다. 설계변수가 아닙니다.

**결정할 것**: 두 겹을 중첩으로 풀지, 하나의 잔차 벡터로 동시에 풀지 — 구현 시 결정

#### `size_motor(MTOW, …)` — ① 모터 사이징

**입력**: MTOW, CT/CP 맵, AERO 곡선, U_eval, `k_mot`

**출력**
- `m_mot`: 모터 질량 [kg] → WGHT, COST
- `I_dash`: dash 전류 [A] → MISS (전류 요구 산정), U_eval 갱신
- `g2`, `g3`: 팁 마하 · 열 한계 판정
- 활성조건: `cruise` 또는 `hover` — 모터 크기를 정한 것이 어느 쪽인지

**계산 — `m_mot`에 대한 결정론적 이분법.** 후보 질량마다:
```
회귀에서 R_mot, I0 조회
dash 작동점 풀이 → 연속 축동력 충족 여부와 나선 팁 마하(g2) 확인
호버 작동점 풀이 → 동손 → THRM.motor_rise 호출 → T_peak ≤ T_limit(g3) 확인
두 조건을 동시에 만족하는 최소 m_mot을 찾은 뒤 k_mot을 곱함
```
주의: 내부 순환(크기 → 저항 → 효율 → 요구동력 → 크기)을 직전 반복값으로 닫지 마세요.
이분법만 순수성을 지킵니다.

#### `evaluate(…)` — ② 성능 평가

**입력**: 확정된 파워트레인(모터·프롭·배터리), 수렴 MTOW, AERO 곡선, U_eval

**출력**
- `margin_V`: 속도 여유 → 성적표 C3
- `SPL_hover`: 호버 소음 [dB] → 성적표 C6
- `kv`: 요구 스펙 시트용 파생값
- `P_hover`: 호버 동력 [W] — 진단 변수

**계산**
```
추력 = 항력 평형을 만족하는 V_max를 1차원 이분법으로 탐색
margin_V = V_max / V_cr
SPL_hover — 앵커 기준점(78 dB @ 3 m)에서 팁속도·추력으로 스케일링
```

### THRM — 모터 열

**입력**
- `P_cu`: 동손 [W] — 순항과 호버 각각의 값을 받음
- `m_mot`, `ar_mot`: 모터 질량과 형상비 — 열용량과 표면적 환산용
- 대류 조건: 비행속도 또는 프롭 후류 속도
- 호버 지속시간, `T_amb`

**출력**
- `T_cruise_ss`: 순항 정상상태 온도 [°C] — 호버 계산의 초기값으로 쓰임
- `T_peak`: 호버 종료 시점 권선 온도 [°C] → PROP `size_motor`
- 열 여유: `T_limit − T_peak`

**계산 — 덩어리(lumped) 열용량 1차 미분방정식**
```
m_mot · c_mot · dT/dt = P_cu − h·A·(T − T_amb)

표면적 A를 m_mot과 ar_mot에서 환산
순항 : 정상상태 해 T_ss = T_amb + P_cu/(h·A)
호버 : T_cruise_ss를 초기값으로 지수 상승, 호버 시간 후가 T_peak
```

> ⚠ **설계상 주의 세 가지**
> 1. 최악 조건은 **착륙 호버**입니다 — 방전 말기라 전압이 낮고, 같은 추력에 전류가
>    커지며, 동손은 전류의 제곱입니다. U_eval 규약과 같은 논리입니다.
> 2. **초기 온도를 외기로 두면 과소평가**입니다 — 착륙 시점 모터는 이미 순항으로
>    데워져 있습니다.
> 3. **대류계수가 구간별로 완전히 다릅니다** — 순항 300 km/h는 강제대류(Re 기반 Nu),
>    호버는 프롭 후류. 상관식을 따로 잡아야 합니다.

**결정할 것**: 호버 지속시간 정의(천이 `t_trans` 기준인가, 이륙·착륙 각각인가),
`T_limit`(권선 절연 등급), `c_mot`, `Nu_corr`

### MISS — 임무 적분 · 배터리 사이징 · 달성 거리

적분기는 하나이고, 사이징용·평가용은 그 진입점입니다.

#### `integrate(…)` — 공용 커널

**입력**: 임무 프로파일(세그먼트 리스트), MTOW, AERO 곡선, 파워트레인, 배터리 상태
**출력**: 에너지·거리·SOC의 시간 이력

**계산 — 고정 스텝 `dt_miss` 전진.** 매 스텝마다:
```
solve_point 호출 → P → I
SOC 감소 → U_ocv(SOC)로 버스 전압 갱신
거리 누적
```
부수 효과: 전압이 떨어지면 같은 추력에 전류가 커지는 말기 악화가 자연히 반영됩니다.

> ⚠ **고정 스텝 필수**: 적응 스텝은 잔차에 인공 노이즈를 만들어 WGHT의 수렴 판정 논리를 흐립니다.

#### `required_energy(MTOW, …)` — ① 배터리 사이징

**입력**: MTOW, `m_mot` (현재 반복의 값) / 요구 임무 프로파일, `R_dash_min` / `k_E` (여유 배율) / `DoD`, `c_rate_max`, `e_spec`

**출력**
- `E_batt`: 배터리 용량 [Wh] → GEOM (치수), COST
- `m_batt`: 배터리 질량 [kg] → WGHT
- 활성조건: `energy` 또는 `power` — 용량을 정한 것이 거리 요구인지 전류 요구인지

**계산 — `E_batt`에 대한 결정론적 이분법.** 후보 용량마다:
```
m_batt = E_batt / e_spec  와  R_pack = k_Rpack · n_ser / cap
integrate 실행 → 요구 거리 도달 시점의 SOC 여유
SOC 여유가 0(DoD 한계)이 되는 최소 용량 → E_energy
전류 요구에서 E_power = I_max / c_rate_max
E_batt = k_E × max(E_energy, E_power)
```

#### `achieved_range(…)` — ② 달성 거리

**입력**: 확정 `E_batt`, 수렴 MTOW, 파워트레인
**출력**: `R_dash` 달성 항속거리 [m] → 성적표 C2
**계산**: 같은 커널을 SOC 소진까지 돌려 누적 거리를 읽습니다. `k_E > 1`이면 R_dash > R_dash_min이 됩니다.

### STRC — 프린트 구조 무게

**입력**: MTOW (현재 반복의 값) / `n_design` (설계 하중배수) / hull 출력, `q_cr`(순항 동압), 핀 법선력 계수

**출력**
- `W_str`: 구조 무게 [kg] → WGHT
- `m_print`: 프린트 재료 무게 [kg] → COST
- `g5`: 응력 여유

**계산**
```
설계 하중 = n_design × MTOW + 공력 하중(핀·동체)
슬라이서 회귀 : 인필율 · 벽두께 · 둘레 수 → 무게
응력 검산으로 g5 여유 산출
```
종속성: MTOW에 반응하는 순수 구조 항입니다. 이전 구조에서는 수렴 루프의 유일한
응답이었고, 지금은 셋 중 하나입니다.

주의: 슬라이서 출력은 레이어 수·둘레 수가 정수라 계단형일 수 있습니다. 그러면 MTOW가
두 값 사이를 진동하는데, 이건 발산이 아니라 `limit_cycle`로 분류됩니다.

### WGHT — 무게 수렴 · 질량 특성

**입력**
- `resp_of`: MTOW를 받아 응답 질량 합을 돌려주는 **순수 함수** — 런처가 조립해서 넘김
- 고정질량: `W_pl + AVIO_LIST 합` — MTOW와 무관한 질량
- 수렴 파라미터: `eps_conv`, `beta`, `N_iter_max` 등

**출력**
- `MTOW`: 최대이륙중량 [kg] → 성적표 C1, 모든 ② 모듈
- `x_cg`: 무게중심 [m] → STAB
- `J_xx`, `J_yy`, `J_zz`: 3축 관성 [kg·m²] → STAB
- `g4`: 수렴 여부 (status 동반)
- `Ŝ`: 성장계수 — 진단 변수
- 질량 분해표: 항목별 질량과 위치

**계산**
```
고정점 반복 : MTOW ← 고정질량 + resp_of(MTOW), 완화계수 beta 적용
잔차비로 성장계수 Ŝ 추정 → 수렴·발산 분류 (§5 ▶사이징 루프 상세)
수렴 후 1회 : x_cg = Σm·x / Σm, 관성은 평행축 정리
```

**항등식**: `MTOW == Σ분해표`를 깨지 않습니다. 질량 항목 분류가 목록을 못 덮는 날,
조용히 틀린 무게가 나가는 대신 거기서 즉시 멈춥니다.

**주입 함수 계약**: `resp_of`는 순수 함수여야 합니다. 같은 MTOW를 넣으면 항상 같은 값이
나와야 하며, 이게 깨지면 배치 실행에서 설계점끼리 오염됩니다.

### STAB — 정적안정 · 천이 조종성

**입력**: `x_cg`, `J_yy` (WGHT) / `x_cp`, `CN_α` (AERO) / `T`, `arm_rotor` (PROP, GEOM) / `q_cr`, `S_ref`, `d_body`, `Δα`, `SM_min`, `k_ctrl`

**출력**
- `SM`: 정적 안정여유 [칼리버] — 진단 변수
- `alpha_max`: 조종 각가속도 [rad/s²] → 성적표 C5
- `g8`: 직진 안정 판정
- `g9`: 천이 조종 판정

**계산**
```
SM = (x_cp − x_cg) / d_body            → g8 판정 : SM ≥ SM_min
M_dist = q·S_ref·CN_α·Δα·|x_cp − x_cg|   — 상수가 아니라 계산값 (§4.4)
조종 모멘트 = 차동 추력 × arm_rotor    → alpha_max = M_ctrl / J_yy
                                       → g9 판정 : 조종 모멘트 / M_dist ≥ k_ctrl
```

> ⚠ **이 구조의 주 병목**: 요구 성능 조건들이 사이징으로 흡수되면서 g8·g9가 주 탈락
> 사유가 될 전망입니다. `S_fin`·`x_fin` 범위 손질이 스크리닝의 우선순위입니다.

### COST — 취득비

**입력**: `m_mot` 또는 연속 출력 (PROP) / `E_batt` (MISS) / `d_prop`, `I_max` (PROP) / `m_print` (STRC) / `AVIO_LIST` (상수 목록)

**출력**: `Cost_acq` 취득비 [KRW] → 성적표 C7

**계산 — 단가 계수 × 각 항을 합산**
```
모터        : c_mot$  × 연속출력
배터리      : c_batt$ × E_batt
프롭        : c_prop$ × 기수
ESC         : c_esc$  × 요구 정격
프린트 재료비 : m_print × 단가
항전        : 목록 합
```
정밀도: C7 가중치가 4.2%라 대표값 수준이면 충분합니다. 여기에 정확도 예산을 쓸 자리가 아닙니다.

## 6. 합격 조건과 성적표

### 6.1 합격 조건

번호는 실행 순서를 따릅니다 — 앞에서 걸리면 뒤는 계산하지 않습니다.

> ⚠ g8·g9가 이 구조의 주 탈락 사유가 될 전망입니다. 요구 성능 관련 조건들이 사이징으로
> 흡수되면서, 남는 실질 병목이 안정성으로 이동합니다. `S_fin`·`x_fin` 범위를 스크리닝에서
> 우선 손질해야 합니다.

## 8. 할 일 목록

각 항목은 **왜 필요한지 → 무엇을 하면 되는지 → 무엇을 내면 되는지** 순으로 적었습니다.

### A. 모델 구현 — 이 판의 새 작업

#### A-1. 순항 트림 연립 구현 · 담당: PROP + AERO
- **왜**: 현행 √(항력²+무게²)는 순항 자세각 51.8°에서 동체 양력을 통째로 버려 요구추력을
  계통적으로 과대평가합니다. 이 오차가 동력→배터리→무게 사슬 전체로 전파됩니다.
- **무엇을**: 미지수 (T, θ)에 대한 2×2 뉴턴 반복. AERO는 항력뿐 아니라 받음각에 따른
  양력 CL(α)을 내주도록 확장이 필요합니다 (현재는 항력 곡선과 CN_alpha만 제공).
- **결정할 것**: 뉴턴 초기값 규칙 · 수렴 판정 기준 · 수렴 실패 시 처리(infeasible 처리 권장) · α와 θ의 관계 정의(순항 비행경로각 가정).
- **산출**: `prop.solve_point` 안의 트림 풀이 + AERO의 CL(α) 인터페이스 추가.

#### A-2. 모터 회귀 계수 · 담당: PROP
- **왜**: DC 모터 모델에 R_mot·I0가 필요합니다. 이 둘이 있어야 부하별 효율이 나오고, 동손이 나와야 열 계산이 성립합니다.
- **무엇을**: 시중 모터 3~5종의 스펙표(질량·kv·내부저항·무부하전류)를 표로 만들고 f(m_mot, kv) 회귀 적합. 벤치 추력 데이터는 불필요합니다.
- **주의**: 표본을 설계 범위에 고르게 — 작은 것부터 큰 것까지. 회귀는 조사 범위 밖에서 무효입니다.
- **산출**: 회귀 계수 (JSON 또는 `constants.py` 상수) + 적합 근거 기록.

#### A-3. 열 모듈 설계 · 담당: THRM (신규 배정 필요)
- **왜**: 호버 가능 여부의 실제 한계는 "순간 출력"이 아니라 모터가 타지 않는가입니다. 이를 고정 배율 상수로 두면 모터 크기가 근거 없이 정해집니다.
- **무엇을 — 시나리오 정의부터**:
  - 호버 지속 시간을 정의합니다 (천이 `t_trans` 기준? 이륙과 착륙 각각?).
  - 최악 조건은 **착륙 호버**입니다 — 방전 말기라 전압이 낮고, 같은 추력에 전류가 커지며, 동손은 전류의 제곱이므로. U_eval 규약과 같은 논리입니다.
  - 초기 온도를 외기로 두면 안 됩니다. 착륙 시점의 모터는 이미 순항으로 데워져 있으므로, 순항 정상상태 온도를 초기값으로 받아야 합니다.
- **무엇을 — 모델**: 덩어리(lumped) 열용량 모델. 발열 = 동손 I²R, 방열 = 대류. 대류계수가 구간별로 완전히 다릅니다 — 호버는 프롭 후류, 순항 300 km/h는 강제대류. 상관식을 구간별로 잡아야 합니다.
- **결정할 것**: `T_limit`(권선 절연 등급 기준) · `c_mot` · `Nu_corr` · `ar_mot`(표면적 환산) · 순항 정상상태 온도 계산 방식.
- **산출**: `modules/thrm.py` + 파라미터 근거 문서.

#### A-4. 외란 모멘트 계산화 · 담당: STAB + AERO
- **왜**: g8·g9가 이 구조의 주 탈락 사유가 될 텐데, 그 판정이 상수 하나에 달려 있으면 DOE 결과 전체가 그 상수에 좌우됩니다.
- **무엇을**: `M_dist = q·S_ref·CN_α·Δα·|x_cp − x_cg|`로 교체. AERO의 `CN_alpha`·`x_cp`, WGHT의 `x_cg`를 받아 씁니다.
- **결정할 것**: Δα(기준 돌풍 받음각) — 운용 환경 가정에서 도출.
- **산출**: `stab.py` 수정 + Δα 근거.

#### A-5. 프롭 앵커 보정의 적용 방식 · 담당: PROP
- **왜**: BEMT는 정지 상태(전진비 J ≈ 0)에서 추력을 크게 예측해 실측 보정이 필요한데, 그 보정 계수가 모든 전진비에 그대로 곱해지면 순항(고전진비, BEMT가 원래 잘 맞는 영역)까지 오염됩니다.
- **무엇을**: 보정을 J의 함수로 감쇠 — J ≈ 0에서 최대, 고전진비에서 1(보정 없음)로 수렴. 새 데이터는 필요 없고 곱하는 방식만 바꿉니다.
- **판단 사항**: 감쇠 함수 형태, 또는 이 처리가 불필요하다는 판단. BEMT 구현하면서 결정.

### B. 값 확정

- **B-1. 물성·단가 상수 · 담당: 조사** — `rho_pack`, `wh_pack`, `rho_mot`(부피 환산 밀도) · `k_Rpack`(팩 내부저항) · `k_mprop`(프롭 질량) · 단가 계수 4종. 품목당 실례 2~3점 확인이면 충분합니다. 회귀 적합이 아니라 대표값 확인입니다.
- **B-2. 설계변수 범위 · 담당: 각 모듈 + 통합** — `d_body`, `lambda_body`, `S_fin`, `x_fin`, `AR_fin`, `d_prop`, `pd_prop` 범위. `pd_prop` 하한은 피치속도 ≥ 1.05·V_cr 규칙으로 산정 (PROP). `k_E`·`k_mot` 범위, `S_fin`·`x_fin` 범위는 스크리닝 DOE 결과로 확정 (통합 + STAB).
- **B-3. 임무·요구 상수 · 담당: 통합 + MISS** — `W_pl`, `R_dash_min`, `t_seg[k]`, `k_trans`, `t_trans`, `DoD`, `c_rate_max`, `e_spec`. `dt_miss`(미션 적분 고정 스텝) — 적분 정확도와 실행 시간의 트레이드오프. 스텝 수렴성 확인 후 결정.
- **B-4. 안정 판정 기준 · 담당: STAB** — `SM_min`(초기값 1.0 cal), `k_ctrl`, `alpha_dot_req`. 시제기 실측 후 갱신.

### C. 코드 정비 — 개편 착수 전

### 11-1. ⓪ 형상 성립 조건 신설 · GEOM

- **왜**: §6.1의 g 목록에 ⓪ 형상 판정이 없습니다(g1은 프롭 항목). 그런데 형상이 성립하지
  않는 조합이 실제로 존재하고, 지금은 음수 길이나 동체 밖 핀이 조용히 뒤로 흘러갑니다.
  예: `lambda_body=5.0`, `x_fin=0.50` → `l_body=0.45`인데 핀 뒷전이 0.585 m라 핀이 동체 뒤
  허공에 붙고, `x_cp/l_body = 1.08`이 나와 STAB의 안정여유가 물리적 의미를 잃습니다.
- **무엇을**: `geom.hull`이 아래 셋을 검사하고 위반 시 `GeomInfeasible` 을 던집니다.
  런처가 받아 사유 코드 `geom_infeasible` 로 탈락시킵니다.
  ```
  l_cyl > 0                    노즈가 전장 안에 들어가는가
  x_fin + c_root ≤ l_body      핀 뒷전이 동체 안에 있는가
  x_fin ≥ l_nose               핀 앞전이 노즈 원추부에 물리지 않는가
  ```
- **왜 g 를 안 만들었나**: g 번호를 늘리면 §6.1 표와 성적표 출력 규격이 함께 바뀝니다.
  탈락 사유 코드는 §5 ▶수렴·발산 분류가 이미 "1급 데이터"로 규정한 채널이라, 거기에
  얹는 편이 파급이 작습니다. DOE 배치가 예외로 죽지 않고 한 줄의 탈락 기록으로 남습니다.
- **대안**: g10 신설. 승인권자 판단.

### 11-2. 포드(모터 나셀) 항력 · AERO

- **왜**: §5.1 AERO의 항력 성분 목록이 "동체 마찰 + 핀 마찰·압력 + 기저 + 간섭"으로
  포드를 뺐습니다. 포드 치수가 모터 질량의 함수라 ⓪에서 알 수 없기 때문인데, 그렇다고
  빼 버리면 4기 나셀의 마찰·형상 항력이 통째로 사라져 §4.1이 경계하는 것과 **반대 방향**의
  계통 오차(과소평가)가 생깁니다.
- **무엇을**: 식은 AERO가 소유하되 포드 치수를 **인자로 받습니다**.
  ```
  F_drag(V, α, pod=(d_pod, l_pod) | None)
  CD0  (V,    pod)   ← cd_pod = Cf(Re_pod)·FF_pod·S_wet_pod/S_ref
                        S_wet_pod = N_rot·π·d_pod·l_pod·k_form
                        FF_pod    = 1 + 0.35/(l_pod/d_pod)
  ```
  곡선 자체는 여전히 설계변수만의 함수라 ⓪가 MTOW를 되먹임 참조하지 않습니다 (§9 위반 아님).
  포드 치수를 아는 시점(① `size_motor` 이후)에 호출부가 넘깁니다.
  `pod=None`이면 포드 항이 0이고, 그건 "아직 안 넘겼다"는 뜻이지 "포드가 없다"가 아닙니다.
- **크기 감각**: 포드 30×45 mm 4기 가정에서 순항 CD0 0.4599 → 0.4801 (+4.4%).
- **미결**: 호출부 배선은 P4(`size_motor`)에서 붙습니다. 그전까지 실효값은 0입니다.

### 11-3. `CL(α)` → `CL(V, α)` · AERO

- **왜**: §5.1은 `CL(α)`로 적었으나 풍축 변환의 축력항 `CD0·sinα`가 V에 의존합니다
  (마찰항의 Re 효과 + 압축성 보정). α만 받으면 순항 CD0로 고정할 수밖에 없고 dash 구간에
  오차가 붙습니다.
- **무엇을**: `CL(V, α, pod=None) = C_N(α)·cosα − CD0(V, pod)·sinα`
- **크기 감각**: α=10°에서 60 m/s 2.9883 vs 120 m/s 2.9910 — **0.09%**. 축력항이 CL에서
  차지하는 비중이 작아 실효 차이는 예상보다 작습니다. 그래도 dash·V_max 탐색에서
  V를 크게 흔들므로 인터페이스는 열어 둡니다.

### 11-4. `HullOut` 젖음면적 분해 · GEOM → AERO

- **왜**: §5.1 GEOM 출력은 `S_wet` 하나인데, §5.1 AERO의 성분별 빌드업은 동체분과 핀분에

  `S_wet`은 둘의 합으로 유지하므로 원문 규격은 그대로입니다.

### 11-5. `AeroOut`의 `CN_alpha_fin`·`q_cr` · AERO → STRC

- **왜**: §5.1 STRC의 입력이 "`q_cr`(순항 동압), 핀 법선력 계수"를 요구하는데 §5.1 AERO의

### 11-6. WGHT 질량 특성의 계산 시점 · WGHT ↔ GEOM

### 11-9. `M_tip_max` 값 충돌 — **P3 에서 수치로 확인됨**

§3.3은 0.7인데, 이전 판 코드에는 0.85와 함께 "300 km/h급은 0.7로는 성립 불가
(스모크 테스트에서 확인)"는 주석이 있었습니다. ICD 우선 원칙대로 **0.7**을 적용했습니다.

P3 에서 BEMT 맵이 서고 나니 이 값이 **지배 제약**임이 수치로 드러났습니다.
프롭 3 × 피치 3 × 동체 3 = 27 설계점 스윕에서, 팁 마하 한계 안에서 요구추력을 낼 수
있는 비율:

| 속도 | 성립 비율 |
|---|---|
| 40 m/s (144 km/h) | 27/27 = 100% |
| **83.3 m/s (300 km/h, V_cr)** | **12/27 = 44%** |
| 110 m/s (396 km/h) | 0/27 = 0% |

무게(0.5 / 1.0 / 2.0 kg)에는 전혀 반응하지 않고 **속도에만** 반응합니다 — 즉 무게
문제가 아니라 팁속도 문제입니다. 기준 설계점(d=0.13 m, pd=1.3)에서:

| 0.75 | 35441 | 1.085 | 23.84 N | 12.65 N | 성립 |
| 0.80 | 38076 | 1.010 | 37.14 N | 12.65 N | 성립 |
| 0.85 | 40694 | 0.945 | 51.70 N | 12.65 N | 성립 |

0.70 → 0.75 사이에서 가용추력이 2배로 뛰는데, 팁 마하가 전진비 J 를 통해 CT 에
비선형으로 먹히기 때문입니다.

**결정: `M_tip_max = 0.70` 유지.** 대신 §2 `pd_prop` 하한 규칙의 계수를 **1.05 → 1.25**

1. `M_tip_max` 는 **물리 한계**고 `pd_prop` 범위는 **우리 선택**입니다. 물리 한계를

3. 원문 m=1.05 가 못 거르는 구멍은 `M_tip_max` 를 올려도 **그대로 남습니다.**

### 11-11. §4.1 트림 연립식이 닫히지 않는다 — **바로잡음**

- **왜**: 원문 §4.1 의
  ```
  T·cosθ + L(α)·sinθ = W        (수직 평형)
  T·sinθ − D(α)·cosθ = 0        (수평 평형)
  ```
  는 어떤 좌표 규약으로도 성립하지 않습니다.
  풍축 L·D(양력은 속도에 수직, 항력은 속도 반대)로 보면 여분의 `sinθ`·`cosθ` 가 남고,
  동체축 N·A 로 보면 같은 힘이 두 식에 함께 나와야 하는데 한쪽에만 나옵니다.
  게다가 본문은 "호버 θ ≈ 90°" 라고 적었는데, 그 식에 θ=90° 를 넣으면 수직 평형이
  `L = W` 가 되어 추력지지가 아니라 양력지지가 됩니다.
- **무엇을** — 규약을 명시하고 식을 바로잡았습니다.
  ```
  θ : 자세각, 수평 기준.  θ=90° 호버(기수 수직),  θ→0 순항(기체 수평)
  α : 받음각.  순항 비행경로각 γ=0(수평비행) 전제 →  α = θ
  T·sinθ + L(V, α) = W        (수직)
  T·cosθ           = D(V, α)  (수평)
  ```
  L=0 이면 `T=√(D²+W²)`, `tanθ=W/D` 로 정확히 환원되고, L>0 이면 T 가 그보다
  작아집니다 — §4.1 이 얻으려던 동체 양력 크레딧이 부호까지 맞습니다.
- **크기 감각** (기준 설계점, V_cr):

  | MTOW [kg] | √(D²+W²) [N] | T_trim [N] | 감소 | θ=α [°] |
  |---|---|---|---|---|
  | 0.5 | 13.367 | 12.488 | −6.6% | 0.62 |
  | 1.0 | 15.836 | 12.646 | −20.1% | 1.24 |
  | 2.0 | 23.223 | 13.271 | −42.9% | 2.44 |
  | 5.0 | 50.585 | 17.495 | −65.4% | 5.92 |

  원문이 인용한 "순항 자세각 51.8°" 와 달리 **1° 내외**가 나옵니다. 핀 면적이 커서
  이 기체는 순항에서 사실상 비행기처럼 날고, 무양력 근사가 버리던 양이 그만큼 큽니다.

### 11-12. 트림 초기값 규칙 · 수렴 판정 · 실패 처리 (§8 A-1 결정 사항)

- **초기값**: 2단 결정론적 규칙.
  ① `qS·CL(V, α) = W` 가 되는 α 를 고정 격자(90등분) 훑기 + 이분법으로 찾아
     `θ₀=α`, `T₀=D(V,α)/cosθ₀` — 순항·dash 의 실제 해가 이 근처입니다.
  ② 양력이 무게를 못 들면 무양력 해 `θ₀=atan2(W,D₀)`, `T₀=√(W²+D₀²)`.
  `CL(α)` 는 큰 α 에서 축력항에 눌려 다시 내려오므로 단조가 아닙니다. 그래서
  이분법을 바로 걸지 않고 **첫 교차 구간**을 격자로 잡은 뒤 그 안에서만 돕니다.
- **수렴 판정**: 잔차 노름 `|(r1, r2)| < eps_trim · W`. 스텝이 아니라 잔차 기준입니다.
- **스텝**: `Δθ` 를 `dtheta_max`(15°)로 제한하고, 잔차 노름이 줄어들 때까지 반으로
  접습니다(백트래킹). `CN_α` 가 16/rad 수준이라 순수 뉴턴은 자세각을 크게 던집니다.
- **실패 처리**: `ok=False` → infeasible. 런처가 사유 코드 `trim_no_solution` 으로 옮깁니다.
- **두 겹 풀이**: **중첩**입니다. 바깥이 트림 2×2, 안쪽이 rpm 1차원 이분법.
  안쪽 `T(n)` 이 단조증가라 이분법이 반드시 수렴하고, 바깥 야코비안이 2×2 로 작아
  안정적입니다. 하나의 3변수 잔차 벡터로 동시에 푸는 안은 CT(J)·CP(J) 테이블 보간의
  기울기 불연속이 야코비안을 오염시켜 채택하지 않았습니다.
- **실측**: 243 케이스 스윕에서 트림 **100% 수렴, 평균 3.22회(최대 4회)**.

### 11-14. `solve_point` 의 rpm 근찾기 대상

§5.1 은 "프롭 요구 토크 = 모터 발생 토크가 되는 rpm 을 1차원 근찾기로 탐색" 이라고
적었는데, 트림이 이미 요구추력 T 를 확정한 뒤라 rpm 은 **추력 조건**으로 이미 결정됩니다
(`CT(J(n))·ρn²D⁴ = T₁`). 남은 자유도는 kv 이고, 그래서 §5.1 이 따로 "kv 는 이 토크
평형의 해로 나옵니다" 라고 적은 것과 앞뒤가 맞습니다. 구현은:

```
n  ← 1차원 이분법 : 프롭 추력 = 요구추력        (상한 = 팁 마하 한계)
kv ← 1차원 이분법 : 모터 요구 전압 = 버스 전압   (R_mot·I0 가 kv 의 함수라 해석해 없음)
```

### 11-15. BEMT 블레이드 규약 — 문서에 없는 가정

§5.1 은 "BEMT" 라고만 적고 블레이드 형상을 정하지 않았습니다. 구현이 쓴 가정:

- 블레이드 수 2, 허브 반경비 0.15, **등코드** `c/D = 0.10`
- **등피치(헬리컬)** 비틀림 — `β(r) = atan(pitch / 2πr)`, `pitch = pd_prop · D`.
  피치비가 정의하는 형상 그 자체입니다.
- 익형: `cl = 5.7·α` (±1.2 클램프), `cd = 0.020 + 0.020·cl²`. Re·마하 의존 없음.
- Prandtl 팁 손실 포함. 유도속도 (v_a, v_t) 를 요소마다 완화 반복으로 닫습니다
  — 유도인자(a, a') 형태는 V=0(호버)에서 0/0 이 되어 쓰지 않았습니다.

**검증**: 추력 0 전진비가 `J₀ = 1.2876`, 피치비 `pd_prop = 1.30` — 등피치 프롭의
알려진 거동(J₀ ≈ 피치비, 익형 항력만큼 조금 아래)과 일치합니다. 최대 효율 0.79 @ J≈1.0
도 소형 2엽 프롭의 통상 범위입니다.

**실행 시간**: `build_map` 이 설계점당 **약 149 ms**. ⓪ 구획에서 가장 무거우며,
DOE 규모 산정(§8 D-1)의 지배 항목이 될 전망입니다.

### 11-16. `solve_point` 에 사이징/평가 두 모드 — **P4 에서 해결**

- **왜**: `_solve_kv` 는 "그 작동점에서 버스 전압을 다 쓰는 kv" 를 푼다. 즉 100%
  스로틀 전제다. 실제 기체는 호버를 부분 스로틀로 하므로, 호버를 이 모드로 풀면
  kv 가 579~716 로 나와 모터 조사 범위(1300~3800) 밑으로 떨어진다.
  그 상태로 동손을 재면 **존재하지 않는 모터의 열**을 계산하게 된다.
- **무엇을**: `solve_point(..., kv=None|값)`
  - `kv=None` **사이징 모드** — kv 를 푼다. dash 처럼 전개를 다 쓰는 점에만 맞다
  - `kv=값` **평가 모드** — 요구 전압 `U_req` 를 낸다. 스로틀 = `U_req/U_bus`
  `size_motor` 는 dash 로 kv 를 정하고 호버는 평가 모드로 본다.

### 11-17. 열 최악 조건이 착륙 호버가 아니다 — g3 를 두 구간 최대값으로

- **왜**: §5.1 THRM 은 "최악 조건은 착륙 호버" 를 전제로 열 여유를 `T_peak` 로만
  적었다. 그건 호버가 지속 고출력인 **통상 멀티로터**의 이야기다.
  이 기체는 300 km/h 순항이 축동력 1.4 kW 를 먹고 호버는 그 1/7 이라,
  **동손 비(5.8)가 대류 비(5.2)를 넘어 순항 정상상태가 더 뜨겁다.**
  그러면 착륙 호버는 오히려 모터를 식힌다.
- **무엇을**: `ThrmOut` 에 `T_hot`·`hot_at` 추가, `margin_T = T_limit − T_hot`.
  어느 쪽이 이기는지는 설계점마다 다르므로 판정하지 않고 **둘 다 계산해 최대값**을 쓴다.
  활성조건(§5.1 size_motor 의 cruise/hover)이 바로 이 `hot_at` 이다 — 실제로
  MTOW 1.0~1.5 kg 에서는 `cruise`, 2.0 kg 에서는 `hover` 로 넘어간다.
- **부수 지적**: §5.1 THRM 주의 1 의 "방전 말기라 전압이 낮고 **같은 추력에 전류가
  커지며**" 는 **팩 전류**에는 맞지만 **모터 전류**에는 안 맞는다. 모터 전류는
  `I = τ/K_t + I0` 라 토크가 정하고 버스 전압과 무관하다. 동손 I²R_mot 도 마찬가지다.
  버스 전압이 낮으면 그 rpm 에 **도달을 못 하는** 것이지 전류가 커지는 게 아니다.
  **확인 필요.**

### 11-18. `pm_mot` 은 제약이 아니라 브래킷 — 그리고 권선 내부 열저항 도입

- **왜**: §3.3 은 `pm_mot` 을 "PROP(**이분법 초기 구간**)" 이라 적었는데 §5.1
  `size_motor` 는 "**연속 축동력 충족 여부**" 를 확인하라고 해 역할이 갈렸다.
  제약으로 읽고 구현해 보니 이 값이 `m_mot` 을 19 g↔116 g(6배), MTOW 를
  0.334↔0.872 kg(2.6배)로 흔드는 **지배 변수**가 됐다. 게다가 3.0 kW/kg 에서는
  모터가 116 g 로 나와 회귀 유효 범위(8.5~76.4 g)를 벗어난다.
- **결정**: **브래킷 전용** (§3.3 문구 채택).
  브러시리스 모터가 어떤 축동력을 *연속으로* 낼 수 있는가는 정의상 권선이 타지
  않는가이고, THRM 이 그걸 순항·호버 각각의 실제 냉각 조건으로 직접 계산한다.
  상수 하나를 별도 제약으로 두면 이중계상이며 ICD **원칙 3(상수보다 해석식)** 위반이다.

  (열만으로 사이징하면 19.4 g 이 나오는데, `R_int=0.2 K/W` 를 넣으면 같은 조건에서
  권선이 136 °C 로 한계를 넘는다). 대류 컨덕턴스와 **직렬**로 넣었다:
  ```
  1/G = 1/(h·A) + R_int_mot
  ```
  열질량은 여전히 하나라 §5.1 의 "덩어리 열용량 1차 미분방정식" 구조를 안 벗어난다.
  `R_int_mot` 은 TBD 지만 `pm_mot` 보다 훨씬 명확한 미지수다 — 모터 1종 열화상 1회로

### 11-23. 배터리 활성조건에 `sustain` 추가

  (사이징된 팩으로 t=14 s 에 이탈).
- **무엇을**: 세 번째 기준 `E_sustain` 을 추가했다 — `sustain_at < 0` 이 되는 최소 용량.

- **미결**: `c_rate_max` 와 `k_Rpack` 은 **함께** 확정해야 한다. 실제 팩 1종의 방전

### 11-28. §4.5 U_eval 순환을 `resp_of` 안에서 닫는다

- **왜**: §5.1 은 `size_motor` 입력에 `U_eval` 을 적고 출력에 "I_dash → **U_eval 갱신**"
  이라고 적었지만 닫는 방법을 안 정했다. 열어 두면 사이징 전압(21.12 V)과 평가
  전압(19.04 V)이 9.9% 갈라지고, 그 결과 **C3 = 0.910 < 1**(설계가 자기 요구속도를
  못 냄), `k_mot`↑ → margin_V↓(거꾸로), 형상을 바꿔도 V_max 가 75.8 에 고정되는
  이상 징후 셋이 한꺼번에 나온다.
- **무엇을**: `resp_of` 안에서 잔차 `f(U) = U_eval(E_batt(U), I_dash(U)) − U` 의
  근을 찾는다. `f` 는 U 에 **단조 감소**다 (전압을 낮게 잡으면 사이징이 kv 를 높여
  전류가 늘고 강하가 커진다). 실측: U 21.12→−2.083, 19.0→−1.135, 17.0→−0.500,
  15.5→+0.054, 13.0→+1.480. 근은 U≈15.5 V.
- **근찾기**: 고정 격자로 브래킷을 잡고 **구간 유지 regula falsi(Illinois)**.
  이분법과 같은 안전성(항상 구간 유지)에 수렴만 빠르다 — 잔차가 매끄러워
  이분법 11회가 2~5회로 준다. 결정론적이라 `resp_of` 의 순수성은 그대로다.
- **대가**: 설계점당 0.83 → 5.06 s. DOE 는 병렬 배치가 사실상 필수다.

### 11-29. `k_mot` 은 `kv` 를 유지한다 — 안 그러면 C3 가 정보를 잃는다

- **왜**: 사이징 모드는 "그 작동점에서 버스를 다 쓰는 kv" 를 준다. `k_mot` 으로
  모터를 키운 뒤 kv 를 **다시 풀면** kv 가 따라 내려가 전압 여유가 0 으로 되돌아가고,
  `V_max ≡ V_cr` 이 되어 **C3 가 모든 설계점에서 정확히 1.0000** 이 된다.
  §2.2 가 `k_mot` 의 트레이드오프를 "더 빠르다(C3) ↔ 무거워진다(C1)" 로 적었는데
  C1 만 나빠지고 C3 는 아무것도 안 사는 상태였다.
- **무엇을**: kv 는 **요구 최소 모터**가 정한다. `k_mot` 여유는 같은 kv 급의 더 큰
  모터를 사는 것이다 — 스테이터가 커져 `R_mot` 이 내려가고, 같은 추력을 더 낮은
  전압으로 내므로 남는 전압만큼 더 빨리 난다.
- **결과**: `k_mot` 1.0→1.4 에서 margin_V 1.0000→1.0630, MTOW 0.664→0.705 kg.

### 11-36. g8 과 g9 는 구조적으로 서로 민다 — `M_dist ∝ SM`

§4.4 의 `M_dist = q·S_ref·CN_α·Δα·|x_cp − x_cg|` 에서 `|x_cp − x_cg| = SM·d_body` 다.
즉 **안정여유를 키우면 외란 모멘트가 정비례해서 커진다.** 실측 확인:
SM=1.083 cal, `|x_cp−x_cg|`=0.0975 m = 1.083×0.09 ✓

그래서 레버가 갈린다:
- `x_fin`↑ · `S_fin`↑ → g8 ↑ 이지만 `M_dist` ↑ 라 **g9 ↓**
- `f_mount`↑ (모멘트암) → `M_ctrl` ↑ 로 **g9 만** 올린다. g8 에 영향 없음
- `thr_dash`↓ (스로틀 여유) → ΔT ↑ → `M_ctrl` ↑ 로 **g9 만** 올린다

16점 격자에서 **동시 만족은 1점뿐**이었다:
`lambda_body`=8.0 · `x_fin`=0.55 · `S_fin`=0.036 · `f_mount`=1.0 → g8 +0.083, g9 +0.085.
저장소 표본 설계점을 이것으로 갱신했다 (g1~g9 전부 통과, C1~C8 전부 실값).

**§5.1 이 지시한 "`S_fin`·`x_fin` 범위 손질이 스크리닝 최우선" 이 정확히 맞았다.**
창이 좁아 DOE 를 그냥 뿌리면 유효 표본 비율이 매우 낮을 것이다.

### 11-37. `thr_dash` 가 g9 로 교차검증됐다 — §11-31 의 약속

§11-31 에서 `thr_dash` 를 "네 모터가 전부 100% 면 조종 권한이 0" 이라는 **조종성

### §11-38 · STRC 를 담당자 코드로 교체 — ICD0-007 어댑터

STRC 담당이 ICD0-007 기준으로 쓴 `strc.py` 를 받았다. **본문을 그대로 두고**
ICD0-008 변환만 `_GeomShim` · `run` 어댑터에 가뒀다. 담당자가 008 로 갱신하면
어댑터만 지우면 된다.

이름 대응 (어댑터가 흡수하는 전부):

| 담당자 (ICD0-007) | ICD0-008 |
|---|---|
| `run(dv, geo, MTOW, fixed)` | `run(dv, hl, aer, MTOW, pod)` |
| `GeomOut` | `HullOut` + `AeroOut` |
| `m_str` / `g10` | `W_str` / `g5` |
| `geo.c_r` / `c_t` | `hull.c_root` / `c_tip` |
| `geo.t_wall` | `k.t_0 + k.k_t·(n_design − n_ref_load)` |
| `geo.d_pod` / `l_pod` / `x_pod` | `geom.pod(...)` — 런처가 넘긴다 |
| `dv.arm_rotor` | `hull.r_body + f_mount·hull.b_fin` (유도값) |

원본 대비 손댄 곳 **다섯 군데**, 전부 `[이식 n/5]` 로 표시:

1. **핀 스팬** — 원본은 "로터축 = 핀 끝"으로 보고 `b_fin = arm_rotor − r_body` 로
   썼다. 008 에는 `f_mount` 가 있어 그 전제가 안 선다. 스팬은 GEOM 의 `b_fin` 을
   쓰고, 루트 모멘트 암만 `arm_rotor − r_body` 로 둔다.
2. **`q_cr` · 핀 법선력 계수를 AERO 에서 받는다** — §5.1 이 정한 입력인데 원본은
   둘 다 자체 계산했다(원본 주석: "AERO 입력은 사용하지 않는다"). 같은 물리량을 두
   모듈이 따로 가지면 §4.6 이 경계하는 발산이 생긴다.
   ⚠ **정규화가 다르다.** 담당자 `CN_alpha_fin` 은 핀 1장·`S_fin_1` 기준이고 AERO
   것은 4장 합·`S_ref` 기준이다. 어댑터가 `CN_α,AERO · S_ref / (N_rot · S_fin_1)`
   로 환산한다. 담당자가 008 로 갱신할 때 **이 정규화를 명시해야 한다.** [확정 필요]
3. **반환을 dict 로** — `StrcOut(m_str·g10)` 매핑을 `run()` 한 곳에 모은다.
4. **쉘 도심** — 원본 `0.5·l_body` 를 `hull.x_wet_body` 로 (§11-35 에서 잡은 버그).
5. **`getattr` 기본값 즉시평가 버그** — `getattr(geo, "arm_rotor", float(dv.arm_rotor))`
   는 `geo.arm_rotor` 가 있어도 `dv.arm_rotor` 를 먼저 건드려 터진다. 지연 평가로
   고쳤다. **원본의 버그이므로 담당자에게 보고한다.**

`constants.py` 에 담당자 코드가 읽는 상수 19개를 추가했다 (§3.9 에 등록). 값이
`strc.py` 안에 숨지 않게 하기 위해서다 (CLAUDE.md 규칙 2).

담당자 기본값과 **우리 값이 다른 11개는 우리 값이 이긴다**:
`phi_0` 0.25(담당 0.15) · `k_phi` 0.05(0.02) · `n_ref_load` 3.0(4.0) ·
`rho_mat` 1240(1200) · `k_sl_shell` 1.15(1.0) · `k_sl_fin` 1.12(1.0) ·
`alpha_lim` 4°(5°) 등. **어느 쪽이 맞는지 팀에서 확정해야 한다.** [확정 필요]

### §11-39 · `w_fill` 양자화 — 수렴 계단, 여유 1.6배

담당자 모델은 루트 보강 폭을 `w_fill = ceil(w_req/w_line)·w_line` 로 **양자화**한다
(슬라이서 압출선 정수배). 그래서 `W_str` 이 MTOW 에 대해 매끄럽지 않고 뛴다.

| | 값 |
|---|---|
| 계단 높이 (`W_str` 점프) | 743 mg |
| 계단 간격 | MTOW 약 0.14 kg |
| WGHT 허용오차 (`eps_conv` 1e-3 × 1.2 kg) | 1200 mg |
| 여유 | **1.6배** |

현재는 수렴한다 (`converged`, n_iter 12, err 8.8e-7). 그러나 `eps_conv` 를 1e-4 로
조이거나 `w_line` 을 키우면 **limit_cycle 이 확실히 난다.** 그때의 진동은 발산이
아니라 이산화이므로 WGHT 가 `limit_cycle` 로 분류하는 것이 맞다 — ICD §5.1 STRC 가
경고한 계단형 출력이 여기서 실제로 확인됐다.

이 계단 때문에 **g5 가 MTOW 에 대해 단조가 아니다**: MTOW 1.0 → 3.0 kg 에서
g5 = +0.075 → +0.019 → +0.009 → +0.002 → +0.054 (톱니). 스크리닝 DOE 에서 g5 를
연속 함수로 가정하면 안 된다. [확정 필요]

### §11-40 · 구조 모델 교체로 예제 설계점이 이동

담당자 모델은 포드 쉘과 핀 외피/코어 분리를 포함해 더 무겁고 더 뒤쪽이다.

| | 이식 전 | 이식 후 |
|---|---|---|
| `W_str` | 659.0 g | 799.1 g |
| 구성 | 쉘 473.5 · 핀 153.5 · 격벽 32.0 | 쉘 473.5 · 핀 248.0 · 포드 58.2 · 루트보강 19.4 |
| MTOW 반응 (1.0→3.0 kg) | 659.0 g **고정** | 797.3 → 808.3 g |
| g5 | +0.9675 고정 (죽은 조건) | +0.002 ~ +0.077 (**살아 있는 조건**) |

늘어난 질량이 x≈0.593 (핀·포드)에 붙어 x_cg 가 후퇴한다. 이전 예제점
(`S_fin` 0.036 · `x_fin` 0.55)은 **SM 0.917 → 0.839 로 g8 불합격**이 됐다.
구조 모델이 바뀐 결과지 이식 버그가 아니다 (쉘 질량 473.5 g 은 양쪽이 동일).

`x_fin` · `S_fin` 12점 스윕으로 재조정했다. §11-36 의 g8·g9 대립이 그대로 보인다:

```

 0.55  0.030 | +0.020  -0.204  +0.739 | 1.219  g8 탈락
 0.58  0.036 | +0.049  +0.016  +0.187 | 1.291  OK
 0.60  0.030 | +0.020  +0.097  +0.126 | 1.219  OK   ← 채택
